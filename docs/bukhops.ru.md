# БухОпс

[English version](bukhops.md)

GitOps берёт состояние кластера из коммитов. БухОпс берёт его из учёта: из журнала хозяйственных операций, который ведётся так, как его ведёт бухгалтерия. Flux проводит то, что сказано в книге, а книга сверяет с собой кластер.

| GitOps | БухОпс |
|---|---|
| репозиторий | главная книга |
| коммит | операция: проводки Дт/Кт и первичный документ |
| файл в репозитории | первичка: манифест на языке 1С, числа в котором — сальдо счетов |
| обязательное ревью | вторая подпись: автор свою операцию не утверждает |
| `git revert` | сторно: те же проводки с минусом, история не переписывается |
| защищённая ветка без force push | операции не меняют и не удаляют |
| заморозка релизов | закрытый период: операции этой датой и раньше не принимаются |
| дрейф | расхождение сверки: «в кластере 3 реплики, а по учёту 5» |
| источник Flux | выписка книги, `ExternalArtifact` |

## Как это работает

```
операции ──► Главная книга ──► Выписка (ExternalArtifact) ──► Групповое перепроведение (Kustomization) ──► кластер
    ▲            │  сальдо, первичка                                                                          │
    │            └────────────────────── сверка: кластер против учёта ◄──────────────────────────────────────┘
 1сctl учёт
```

Обработка `glavnaya-kniga`, написанная на языке 1С, как все операторы Assnetes, проводит каждую книгу:

1. берёт операции книги в порядке дат и решает, какие учесть: вторая подпись другого человека из подписантов книги, дата после закрытого периода, оба счёта каждой проводки есть в плане счетов, сторно зеркально учтённой и ещё не сторнированной операции;
2. запоминает отпечаток каждой учтённой операции; если её потом поменяли в обход проверок, книга перестаёт публиковать выписки, пока документ не восстановят;
3. сворачивает проводки в сальдо по счетам и выполняет первичку учтённых несторнированных операций, давая ей `Сальдо("01/Витрина")`; по каждому объекту действует последняя редакция;
4. упаковывает объекты в архив, который для той же книги совпадает байт в байт, подшивает его в справочник `<книга>-vypiska` и объявляет как `ExternalArtifact`; выписку Flux отдаёт любая реплика обработчика, порт 9090;
5. создаёт `Kustomization` Flux — групповое перепроведение, которое проводит выписку с удалением лишнего;
6. раз в минуту сверяет объекты выписки с кластером и пишет расхождения в состояние книги.

Проверки заполнения той же обработки отказывают раньше, чем изменение попадёт в учёт: операция, подписанная чужим именем; утверждение собственной операции; подпись не подписанта книги; дата в закрытом периоде; исправление и удаление операции; сторно, не зеркальное своей операции; удаление книги; открытие периода не подписантом. Проверки — вебхук допуска с `failurePolicy: Ignore`, как у всех проверок Assnetes; при проведении книга применяет те же правила ещё раз.

## Что нужно

Flux 2.7 или новее с включённым feature gate `ExternalArtifact` у kustomize-controller. Во Flux 2.9.5 он по умолчанию всё ещё выключен:

```bash
flux install --components=source-controller,kustomize-controller
kubectl -n flux-system patch deploy kustomize-controller --type json \
  -p '[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--feature-gates=ExternalArtifact=true"}]'
```

Обработка входит в пакет `assnetes-obrabotki`; без Flux книга ведёт учёт и пишет, что Flux не установлен.

## Книга

```bsl
Книга = Новый ГлавнаяКнига("Основная", "Бухгалтерия");
Книга.Спецификация.Подразделение = "Ромашка";      // куда проводятся документы
Книга.Спецификация.Подписанты.Добавить("tamara.petrovna");

Счёт = Книга.Спецификация.ПланСчетов.Добавить();
Счёт.Код = "01";
Счёт.Наименование = "Основные средства";

Счёт = Книга.Спецификация.ПланСчетов.Добавить();
Счёт.Код = "80";
Счёт.Наименование = "Уставный капитал";
Счёт.Вид = "Пассивный";

Провести(Книга);
```

## Операция

```bsl
Операция = Новый Операция("БП-000001", "Бухгалтерия");
Операция.Спецификация.Книга = "Основная";
Операция.Спецификация.Дата = "2026-09-01";
Операция.Спецификация.Содержание = "Принята к учёту витрина";

Проводка = Операция.Спецификация.Проводки.Добавить();
Проводка.Дт = "01/Витрина";     // счёт 01, субконто «Витрина»
Проводка.Кт = "80";
Проводка.Сумма = 2;

Операция.Спецификация.Первичка =
"Развёртывание = Новый Развёртывание(""Витрина"");
|Развёртывание.Спецификация.Реплики = Сальдо(""01/Витрина"");
|...
|Провести(Развёртывание);";

Провести(Операция);
```

`1сctl провести` заполняет `Автор` пользователем, которого видит кластер. Полный пример с ролями бухгалтеров и главбуха — в [examples/bukhops](../examples/bukhops).

## 1сctl учёт

```console
$ 1сctl провести --файл bp-000002.bsl                  # операцию проводит автор
$ 1сctl --от-имени tamara.petrovna учёт утвердить БП-000002
$ 1сctl учёт операции                                  # журнал: проводки, подписи, учтена ли и почему нет
$ 1сctl учёт сторно БП-000003                          # сторнирующая операция, её утверждают как любую
$ 1сctl учёт закрыть-период 2026-09-30
$ 1сctl учёт сверка                                    # ревизия, разнесена ли, расхождения
$ 1сctl учёт осв                                       # оборотно-сальдовая ведомость за открытый период
```

`--от-имени` действует от имени другого пользователя (impersonation). ОСВ — запрос к регистру бухгалтерии языка запросов:

```console
$ 1сctl запрос 'ВЫБРАТЬ * ИЗ РегистрБухгалтерии.Хозрасчётный.ОстаткиИОбороты КАК О'
```

## Ограничения

Первичка проводит объект целиком: две операции об одном объекте не сливаются, поздняя заменяет раннюю. Сальдо — числа; всё, что не число, например образ, живёт в первичке. Выписка хранится в справочнике (ConfigMap), поэтому объекты одной книги в упакованном виде должны уместиться в мегабайт.
