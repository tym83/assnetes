# Assnetes («1С:Оркестратор 8») — дизайн

Черновик для обсуждения, 25.10.2026. Английская версия появится перед публикацией.

## 1. Что это

Дистрибутив Kubernetes, в котором:

1. вместо YAML пишут на встроенном языке 1С (кириллическом);
2. операторы Kubernetes пишут на том же языке: среда исполнения берёт на себя всю механику контроллера, а логика живёт в модулях `.bsl`;
3. пакетный менеджер (kubepkg) ставит в кластер 1С:Предприятие, 1С:Бухгалтерию, «Торговлю и склад», 1С:CRM и 1С-Битрикс, а их операторы в духе CloudNativePG ведут весь жизненный цикл: создание, обновление конфигурации, бэкапы, горизонтальное и вертикальное масштабирование;
4. управлять кластером и набором кластеров можно из GUI в привычном бухгалтеру стиле;
5. CLI, GUI и операторы разговаривают с пользователем как бухгалтерия.

Принцип тот же, что у Tatarnetes и Sheeternetes: шутка снаружи, а внутри всё работает по-настоящему. Если 1С поставилась в под и бухгалтер открыл базу в браузере — это настоящая 1С в настоящем кластере. Ворчание — это слой поверх правильного поведения, а не вместо него. Скрипты и CI получают чистый вывод и коды возврата.

## 2. Что выяснилось на исследовании и что ограничивает дизайн

| Факт | Следствие |
|---|---|
| Дистрибутивы платформы 1С нельзя распространять: так говорят лицензия community и README всех известных образов | Образов с 1С в публичном реестре не будет. Пакет поставляет «скелет», а платформу пользователь приносит сам (BYO, как `msttcorefonts` в Debian). Сборка образа идёт внутри кластера, в его приватный реестр |
| Платформу без ИТС можно легально скачать на developer.1c.ru (лицензия для разработчиков) или как учебную версию | Для стенда есть легальный путь: лицензия для разработчиков даёт сервер, до 3 сеансов, 1 веб-сеанс, недельная лицензия с автопродлением |
| Шаблоны Бухгалтерии, Управления торговлей и CRM (`.cf`, `.cfu`) без ИТС или купленной коробки легально не получить | Пакеты прикладных решений принимают шаблон из Secret или OCI-артефакта. Для демо можно взять учебные конфигурации из учебной версии или пустую конфигурацию с нашей демо-обработкой |
| «Торговля и склад» — это 7.7, только Windows, обновления прекращаются с 01.01.2027 | Пакет `торговля-и-склад` честно ставит наследника, Управление торговлей 11. Ностальгическая 7.7 в Windows-ВМ через KubeVirt — опционально и позже, на чужом образе Windows и чужой поставке |
| Битрикс и Битрикс24 «коробка» публично скачиваются как 30-дневная пробная версия, есть официальная контейнерная среда (GPL-3.0, quay.io/bitrix24) | Битрикс — единственный продукт, который поставится «из коробки» без BYO |
| Сервер 1С: ragent/rmngr/rphost, клиент ходит напрямую на `хост:порт` рабочего процесса. Имя хоста записано в реестр кластера, лицензия привязана к железу | Рабочие серверы — StatefulSet со стабильными DNS-именами. Сервис лицензирования вынесен на отдельный под, прибитый к ноде, с фиксированными hostname и MAC (правило `rac rule ... LicenseService always`) |
| `ibcmd` умеет создать базу, загрузить `.cf`/`.cfe`/`.dt` и применить конфигурацию без Конфигуратора. Для `.cfu` нужен Конфигуратор | Почти весь жизненный цикл идёт через `ibcmd` и `rac` в Job-ах. Обновление поставки `.cfu` — через Конфигуратор под Xvfb, отдельным шагом |
| Нужен PostgreSQL с патчем 1С. Postgres Professional бесплатно публикует сборку «PostgreSQL для 1С» (repo.postgrespro.ru/1c). CNPG принимает любой образ с нужными бинарниками | СУБД = CloudNativePG с нашим образом «CNPG + PostgreSQL для 1С 17» — его можно публиковать: это свободное ПО |
| Готового k8s-оператора для 1С не существует. Есть только заброшенный Helm-чарт kubeonec (2021) | Мы первые, и это надо сделать хорошо |
| Интерпретатора языка 1С на Go нет. OneScript 2.2 есть, но его HTTPS-клиент не проверяет сертификат сервера и не умеет клиентские сертификаты, а клиента Kubernetes под него нет | Пишем свой интерпретатор подмножества языка на Go (`pkg/bsl`). OneScript остаётся эталоном семантики. GPL-грамматику 1c-syntax не копируем |
| Kubernetes принимает кириллические имена полей в схемах CRD (проверено на кластере), но `kind`, имена объектов, метки и группы API — только латиница. CEL кириллицу не понимает | Свои CRD имеют кириллические поля прямо в etcd (`spec.Конфигурация`, `spec.Реплики`). Kind и группа — латиница/punycode, а клиент везде показывает русские названия |

## 3. Слои

```
┌─────────────────────────────────────────────────────────────────┐
│ GUI «Такси-подобный» (веб)      CLI `главбух`      Персоны      │
├─────────────────────────────────────────────────────────────────┤
│ Язык: интерпретатор встроенного языка на Go (pkg/bsl)           │
│   ├ манифесты .bsl → объекты API                                │
│   ├ язык запросов (ВЫБРАТЬ … ИЗ Кластер.Поды …)                 │
│   └ среда исполнения операторов (Обработки)                     │
├─────────────────────────────────────────────────────────────────┤
│ Операторы на языке 1С: Предприятие, Бухгалтерия, Торговля,      │
│ CRM, Битрикс + 5 примеров общего назначения                     │
├─────────────────────────────────────────────────────────────────┤
│ kubepkg (встроен, своя группа API) + репозиторий «Прайс-лист»   │
├─────────────────────────────────────────────────────────────────┤
│ Любой Kubernetes ≥1.33   или   дистрибутив kuberoot `assnetes`  │
└─────────────────────────────────────────────────────────────────┘
```

Assnetes ставится двумя способами:

- **на любой Kubernetes** — метапакетом kubepkg (основной путь, в нём и тестируемся на Hetzner);
- **как дистрибутив на железо** — профиль kuberoot `assnetes` (ядро, kinit, node API, kubepkg уже внутри). Это последняя фаза: kuberoot уже умеет всё нужное, нам остаётся профиль и метапакет.

## 4. Язык

### 4.1. Интерпретатор (`pkg/bsl`)

Свой лексер, парсер (рекурсивный спуск) и вычислитель на Go. Подмножество языка:

- ключевые слова — все русские и английские из OneScript (`Если/If`, `Для Каждого`, `Попытка`, `Новый`, `Перем`, `Знач`, `Экспорт`, `#Область`, `#Использовать`, аннотации `&Имя(...)`);
- регистр не важен, `=` означает и присваивание, и сравнение, строки с продолжением `|`, даты `'20260101'`;
- типы: Число (десятичное, как в 1С — `0.1 + 0.2 = 0.3`, бухгалтер не простит), Строка, Дата, Булево, Неопределено, Null;
- коллекции: Структура, ФиксированнаяСтруктура, Соответствие, Массив, ТаблицаЗначений, СписокЗначений;
- функции: СтрШаблон, СтрРазделить, СтрСоединить, Формат (с `ЧГ`, `ЧДЦ`, `ДФ`), ЗначениеЗаполнено, ТипЗнч/Тип, ПрочитатьJSON/ЗаписатьJSON, ТекущаяДатаСеанса, Сообщить, ВызватьИсключение, ИнформацияОбОшибке;
- без метаданных, форм и клиент-серверных директив (`&НаСервере` разбирается и игнорируется — «у нас всё на сервере»).

Интерпретатор детерминирован и ограничен: лимит шагов и памяти, никакого `Выполнить()` строк из объектов кластера. Манифест не может сходить в сеть, а оператор может — через объект `Кластер` и разрешённые HTTP-клиенты.

`ТекущаяДата()` работает, но линтер `главбух проверить` ругается, как BSL LS: «используйте ТекущаяДатаСеанса(), вы же не в 2009 году».

### 4.2. Манифесты вместо YAML

Манифест — модуль `.bsl`, где объекты создаются конструкторами и «проводятся». Проводка = server-side apply.

```bsl
#Область Бухгалтерия

Развёртывание = Новый Развёртывание("бухгалтерия-фронт");
Развёртывание.Метаданные.ОбластьИмён = "ромашка";
Развёртывание.Метаданные.Метки.Вставить("приложение", "бухгалтерия");
Развёртывание.Спецификация.Реплики = 2;

Контейнер = Развёртывание.Спецификация.Шаблон.Спецификация.Контейнеры.Добавить();
Контейнер.Имя = "веб";
Контейнер.Образ = "registry.local/apache-1c:8.3.27";
Контейнер.Ресурсы.Запросы.Процессор = "500m";
Контейнер.Ресурсы.Пределы.Память = "1Gi";

Провести(Развёртывание);

ИБ = Новый ИнформационнаяБаза("бухгалтерия");
ИБ.Спецификация.Конфигурация = "БухгалтерияПредприятия";
ИБ.Спецификация.Редакция = "ПРОФ";
ИБ.Спецификация.КластерСерверов = "основной";
ИБ.Спецификация.Пользователей = 10;
Провести(ИБ);

#КонецОбласти
```

- Словарь «поле API ↔ русское название» генерируется из OpenAPI кластера. Ключевые поля переводятся вручную и с душой (`Развёртывание`, `ОбластьИмён`, `Реплики`, `Образ`, `Запросы`, `Пределы`), остальное транслитерируется обратимо. Можно писать и по-английски (`Развёртывание.spec.replicas`): так делают и в 1С.
- Ключи меток вида `app.kubernetes.io/name` — через `Соответствие` (`Метки.Вставить(...)`), как и положено в 1С.
- Имена объектов: русское имя → `metadata.name` по транслиту ГОСТ 7.79, оригинал хранится в аннотации `оркестратор.бух/наименование`. Это реквизиты «Код» и «Наименование» справочника 1С, так что всё по канону.
- `главбух провести файл.bsl` = apply; `главбух распровести` = delete, а точнее пометка на удаление (см. 7); `главбух выгрузить под/x --в bsl` превращает живой объект обратно в `.bsl`.
- Плагин kubectl `kubectl bsl` для тех, кто не готов к `главбух`.

### 4.3. Язык запросов к кластеру

`главбух запрос` выполняет подмножество языка запросов 1С над объектами кластера:

```
ВЫБРАТЬ
    Поды.ОбластьИмён КАК Подразделение,
    КОЛИЧЕСТВО(Поды.Имя) КАК Всего,
    СУММА(ВЫБОР КОГДА Поды.Фаза = "Running" ТОГДА 1 ИНАЧЕ 0 КОНЕЦ) КАК Работает
ИЗ
    Кластер.Поды КАК Поды
ГДЕ
    Поды.Имя ПОДОБНО "бух%"
СГРУППИРОВАТЬ ПО
    Поды.ОбластьИмён
УПОРЯДОЧИТЬ ПО
    Всего УБЫВ
```

Плюс виртуальные таблицы регистров:

- `РегистрНакопления.РесурсыУзлов.Остатки(&НаДату)` — сколько CPU и памяти осталось на нодах, из allocatable минус requests;
- `РегистрНакопления.Рестарты.Обороты(&Начало, &Конец, Час)` — рестарты контейнеров за период, из метрик.

Это и есть оборотно-сальдовая ведомость кластера. Реализация: таблицы строятся из informer-кэша, движок группировок свой. В операторах доступен тот же `Новый Запрос`.

## 5. Операторы на языке 1С

### 5.1. Модель

Оператор = «Обработка»: каталог с `Обработка.bsl` и описанием CRD. Среда исполнения `обработчик` (Go, controller-runtime) берёт на себя informers, очереди, повторы с backoff, server-side apply, финализаторы, события, статус, вебхуки, метрики и выборы лидера («монопольный режим»). Логика оператора — обработчики событий, названные так же, как события модуля объекта в 1С:

| Событие 1С | Что делает в Kubernetes |
|---|---|
| `ОбработкаПроведения(Объект, Отказ)` | reconcile: привести мир к объекту |
| `ОбработкаПроверкиЗаполнения(Объект, Отказ, ПроверяемыеРеквизиты)` | validating webhook |
| `ПередЗаписью(Объект, Отказ)` | mutating webhook (заполнение по умолчанию) |
| `ПередУдалением(Объект, Отказ)` | финализатор: убрать за собой |
| `ПриИзмененииРеквизита(Объект, Реквизит)` | реакция на изменение конкретного поля |
| `РегламентноеЗадание()` с `&Расписание("0 9 25 * *")` | периодическая работа |

```bsl
&Обработка(Вид = "Infobase", Группа = "оркестратор.бух", Владеет = "StatefulSet, Job, Service")
&МонопольныйРежим

#Область ОбработчикиСобытий

Процедура ОбработкаПроведения(Объект, Отказ) Экспорт

    Если НЕ ЗначениеЗаполнено(Объект.Спецификация.КластерСерверов) Тогда
        Отказ = Истина;
        Сообщить("Не указан кластер серверов. Без первички не проведу.");
        Возврат;
    КонецЕсли;

    Задание = СоздатьЗаданиеСозданияБазы(Объект);
    Кластер.Провести(Задание, Объект);   // второй параметр — владелец

    Объект.Статус.Состояние = "Проведён";
    Объект.Статус.Сообщение = СтрШаблон("База %1 создана на кластере %2",
        Объект.Метаданные.Имя, Объект.Спецификация.КластерСерверов);

КонецПроцедуры

#КонецОбласти
```

Встроенные объекты: `Кластер` (Получить, Выбрать, Провести, ПометитьНаУдаление, ВыполнитьВПоде, ЗаписатьСобытие), `Запрос`, `HTTPСоединение` (с нормальной проверкой TLS, в отличие от OneScript), `Секреты`, `Журнал`.

Операторы продуктов 1С написаны на этом же языке — 1С управляется на 1С. Что требует надёжности (exec в под, ожидание Job, SSA), берёт на себя Go-часть среды исполнения, а в `.bsl` остаётся бизнес-логика жизненного цикла.

### 5.2. Пять примеров полезных операторов

Каждый полезен и вне шутки, и каждый короткий — это витрина SDK.

1. **КурсыВалют.** Раз в день тянет курсы ЦБ РФ (ещё ЕЦБ и НБ РК) в ConfigMap и считает стоимость каждой области имён по requests и прайсу за ядро и гигабайт в рублях, долларах, евро и тенге. На выходе — FinOps-отчёт «Расходы по подразделениям». `kubectl top` с колонкой «Стоимость, руб.».
2. **ПроизводственныйКалендарь.** CRD с производственным календарём РФ (и других стран), синхронизация с открытым источником. Вебхук запрещает выкатку в праздники, выходные и после 15:00 в предпраздничный сокращённый день. Это change freeze по-взрослому, с исключениями «по служебной записке» (аннотация с обоснованием и подписью).
3. **ДатаЗапретаИзменения.** Аннотация на области имён: правки объектов закрытого периода отклоняются («Период закрыт. Обратитесь к главному бухгалтеру»), разрешены только группе «главбух». Реальная защита прод-конфигурации от правок задним числом.
4. **УдалениеПомеченных.** `главбух распровести` только помечает объект (финализатор плюс красный крестик в GUI). Регламентное задание ночью удаляет помеченное, если на объект нет ссылок (ownerReferences, тома, сервисы, ингрессы, секреты в подах), иначе пишет «Не удалён: на объект есть ссылки (14)». Безопасное удаление, которого в Kubernetes не хватает.
5. **АктСверки.** Сравнивает объекты кластера с Git-репозиторием («данные контрагента») и выпускает акт сверки: расхождения, кто прав, подпись сторон. Drift detection, который работает и без Flux и Argo. Акт выгружается в PDF в форме настоящего акта сверки взаиморасчётов.

## 6. Пакеты и операторы продуктов

### 6.1. Пакетный менеджер

kubepkg встраивается как библиотека (`pkg/operator`, `pkg/cli`) со своей группой API `пакеты.бух` (punycode). Репозиторий пакетов называется «Прайс-лист», это подписанный индекс на GitHub Pages. CLI: `главбух закупить бухгалтерия`, `главбух прайс`, `главбух остатки` (что установлено), `главбух сторно бухгалтерия` (rollback).

### 6.2. Состав «Прайс-листа»

| Пакет | Что ставит | Откуда бинарники |
|---|---|---|
| `postgresql-1c` | CNPG + образ «PostgreSQL для 1С 17» | публичный образ, собираем сами из repo.postgrespro.ru/1c |
| `1c-predpriyatie` | оператор платформы, CRD, сборщик образа | BYO: архив платформы из Secret/URL → Job сборки → приватный реестр кластера |
| `1c-buhgalteriya` | Бухгалтерия предприятия 3.0 (ИБ + публикация) | BYO: шаблон `.cf`/`.dt`; демо — учебная конфигурация |
| `torgovlya-i-sklad` | Управление торговлей 11 под ностальгическим именем | BYO |
| `1c-crm` | 1С:CRM, отдельная база или УТ+CRM | BYO |
| `1c-bitrix` | Управление сайтом (Старт…Энтерпрайз), пробная версия 30 дней | публично |
| `bitrix24` | Битрикс24 «коробка», пробная версия | публично |
| `assnetes` | метапакет: операторы-примеры, GUI, персоны, календарь | наш код |

Если платформу не принесли, пакет ставится, но ИБ висит в статусе «Ожидает поставку: не обнаружен дистрибутив платформы. Обратитесь к партнёру 1С» — и это не шутка, а реальный статус с инструкцией.

### 6.3. Оператор платформы 1С

CRD (kind латиницей, поля кириллицей):

| Kind | Русское имя | Что это |
|---|---|---|
| `Platform` | Поставка | версия платформы, откуда взять архив, собранный образ |
| `ServerCluster` | КластерСерверов | центральный сервер, рабочие серверы, лицензирование, параметры кластера |
| `Infobase` | ИнформационнаяБаза | база на кластере: СУБД, конфигурация, расширения, пользователи, бэкапы |
| `Publication` | Публикация | Apache + wsap24 + `default.vrd`: веб-клиент, HTTP-сервисы, OData |
| `Standalone` | АвтономныйСервер | `ibsrv` с файловой базой, одна реплика — режим «базовой» редакции |
| `InfobaseBackup` | Выгрузка | бэкап: `.dt` или физический через CNPG |
| `ConfigurationUpdate` | ОбновлениеКонфигурации | заявка на обновление `.cf`/`.cfu`/`.cfe` с окном работ |

Устройство `ServerCluster`:

- **центральный сервер** — под StatefulSet `…-central-0`: ragent, rmngr, ras. Реестр кластера на PVC, hostname = имя пода, стабильный DNS через headless-сервис;
- **сервер лицензирования** — правило `LicenseService always` на одном поде, прибитом к ноде (local PV `/var/1C/licenses`, фиксированный MAC через аннотацию CNI). Переезд пода на другую ноду требует повторной активации, и оператор честно говорит об этом;
- **рабочие серверы** — StatefulSet `…-worker-N`, каждый регистрируется `rac server insert`, правила `rac rule apply` распределяют ИБ;
- клиенты внутри кластера (публикации) ходят на поды по DNS. Наружу кластер серверов не торчит: пользователи заходят через веб-публикацию.

**Горизонтальное масштабирование** («приём на сезонную работу»):

- вверх: `spec.РабочиеСерверы.Количество` растёт → новый под → `rac server insert` → `rac rule apply` → сервер принимает сеансы;
- вниз: сервер исключается из правил → новые сеансы на него не идут → ждём, пока активные сеансы закончатся (с тайм-аутом и сообщением пользователям «Сеанс будет завершён через 15 минут») → `rac server remove` → под удаляется. Событие: «Уволен по истечении срочного трудового договора»;
- автоматически: собственный автоскейлер по числу сеансов и загрузке rphost из `rac process list` (метрики экспортируются в Prometheus), с ограничением сверху числом лицензий.

**Вертикальное масштабирование** («повышение оклада по служебной записке»):

- изменение ресурсов пода на месте (in-place resize, Kubernetes ≥1.33) без перезапуска сеансов;
- синхронно — параметры сервера через `rac server update`: `--safe-working-processes-memory-limit`, `--critical-total-memory`, `--infobases-limit`, `--connections-limit`;
- если на месте нельзя — по одному поду с дренажом сеансов.

**Жизненный цикл ИБ:**

1. Создание: `ibcmd infobase create --create-database` из `.cf` или `.dt`, затем `rac infobase insert` на кластер.
2. Обновление конфигурации: блокировка сеансов с кодом разрешения → рассылка «Выйдите из базы!» → завершение сеансов → бэкап → `ibcmd config load/apply` (`.cf`, `.cfe`) или Конфигуратор под Xvfb (`.cfu`) → первый запуск обработчиков обновления → снятие блокировки. Окно работ берётся из производственного календаря. Цепочка релизов `.cfu` применяется последовательно, как положено.
3. Бэкапы: физические и PITR — через CNPG; `.dt` по расписанию для переноса. Перед любым обновлением бэкап обязателен: «Выгрузку .dt сделали?»
4. Обслуживание: «Тестирование и исправление» (реиндексация, пересчёт итогов) по расписанию, сброс зависших rphost, перезапуск процессов по лимиту памяти.
5. Удаление: пометка → бэкап → `rac infobase drop` → удаление БД.

**Лицензии.** Режимы: `community` (лицензия для разработчиков: активация через под лицензирования с выходом в интернет, лимит 3 сеанса — оператор знает о нём и не масштабирует бессмысленно), `software` (PIN-коды из Secret, одна лицензия на каждый рабочий сервер — оператор считает и предупреждает), `hasp-network` (адрес сетевого менеджера лицензий). Лимит лицензий — это ResourceQuota-подобная проверка: лишний рабочий сервер не создаётся («Нет свободной лицензии»).

### 6.4. Прикладные решения

`1c-buhgalteriya`, `torgovlya-i-sklad`, `1c-crm` — тонкие операторы поверх `Infobase`: знают свою конфигурацию, матрицу «релиз → минимальная платформа», редакцию (базовая → `Standalone`, ПРОФ/КОРП → `ServerCluster`), профиль ресурсов (малый/средний/большой из исследования) и обмены:

- **Обмен** (CRD `ExchangeLink`, «ПланОбмена») между базами: EnterpriseData (УТ → Бухгалтерия), CommerceML (УТ → Битрикс), РИБ (центральная база ↔ филиалы в разных кластерах). Транспорт — S3-каталог или HTTP-сервис через ингресс. Это мультикластерная федерация на родных механизмах 1С.

### 6.5. Оператор Битрикса

CRD `BitrixSite` («Сайт»):

- web: nginx + php-fpm, Deployment с HPA по CPU (горизонтальное масштабирование);
- cron: ровно один экземпляр для агентов (`BX_CRONTAB_SUPPORT`), иначе агенты задвоятся;
- push: pub/sub + Redis;
- кэш и сессии в Redis, файлы `upload/` — RWX-том или S3;
- БД: MariaDB/Percona через их оператор, либо PostgreSQL через CNPG (редакции Pro/Enterprise);
- ядро Битрикса само себя переписывает при обновлении, поэтому код живёт на RWX-томе. Обновление ядра делает один под в «монопольном режиме», остальные потом перечитывают код;
- редакция «Энтерпрайз» включает веб-кластер: слейвы MySQL и балансировку чтения;
- лицензионный ключ — в Secret, пробный период отслеживается: «До окончания пробного периода 3 дня. Оплатите счёт».

## 7. Голос бухгалтерии

### 7.1. Движок фраз

Каталоги фраз — в `data/*.po` (переводится PR-ом без кода, как в Tatarnetes). Фраза выбирается по ситуации (успех, отказ, ошибка, ожидание, удаление), персоне, календарю и «настроению». Правила, вынесенные из Tatarnetes:

- шутки только при интерактивном терминале; при `--output json`, в pipe и в CI вывод чистый;
- задержки («у меня обед») — только при tty и только 12:00–13:00 по часовому поясу кластера, отключаются `--я-директор` или переменной окружения;
- под каждым смешным сообщением — настоящее сообщение Kubernetes, мелко: смысл ошибки не должен теряться.

### 7.2. Персоны

| Персона | Компонент | Как говорит |
|---|---|---|
| Тамара Петровна, главбух | admission, RBAC, cluster-admin | «А кто это согласовывал?», «Период закрыт», «Сначала служебку на моё имя» |
| Леночка, младший бухгалтер | подсказки, мастера | «Ой, это надо у Тамары Петровны спросить», «Я ничего не нажимала» |
| Валентина Ивановна, кассир | ингресс, ограничение частоты | «Касса закрыта», 429 с `Retry-After: после обеда` |
| «Девочки из бухгалтерии» | лента событий в GUI | «Девочки, у кого тоже 1С висит?» |
| Инспектор ФНС | внешние политики, сканер | «Требование о представлении пояснений в течение 5 рабочих дней» |
| Аудитор | отчёт политик | «Существенные замечания, не влияющие на достоверность» |
| Директор | подтверждения опасных действий | «Где подписать?», «Почему так дорого?!» |
| Димон, 1С-ник с франчайзи | обновления, диагностика | «А ИТС продлили?», «Это типовая ошибка, ставьте последний релиз» |

### 7.3. Перевод ошибок

Пары «ошибка Kubernetes → ошибка 1С» с оригиналом под ней:

| Kubernetes | Assnetes |
|---|---|
| `the object has been modified; please apply your changes to the latest version` | Данные были изменены или удалены другим пользователем (сеансом)! |
| `Forbidden` | Недостаточно прав для выполнения операции. Обратитесь к главному бухгалтеру |
| `exceeded quota` | Нет свободной лицензии. Лимит по статье исчерпан, приходите в следующем квартале |
| `OOMKilled` | Процесс rphost завершён аварийно. Списано по акту |
| `NotFound` | <Объект не найден> (412:9a8b…) |
| `AlreadyExists` | Попытка вставки неуникального значения в уникальный индекс |
| `Insufficient cpu` | Не хватает «Процессор» на складе «ws3»: требуется 2, остаток 0,5 |
| `context deadline exceeded` | Конфликт блокировок при выполнении транзакции: превышено максимальное время ожидания |
| CRD-схема не совпадает | Конфигурация базы данных не соответствует сохранённой конфигурации. Продолжить? |

### 7.4. Календарь

Настоящий налоговый календарь с переносами по производственному календарю: 25-е (уведомления, отчётность — бухгалтерия на взводе, отказы резче), 28-е (ЕНП), 31 марта (годовая), закрытие месяца в первые 5 рабочих дней, **21 ноября — День бухгалтера** (все отказы вежливые и заканчиваются «С праздником!»).

## 8. GUI

Веб-приложение «под Такси», но с собственной палитрой и без логотипа 1С (пародия, а не копия — см. 11).

- **Список информационных баз** при входе = список кластеров (контексты kubeconfig как `ibases.v8i`), группы, «Добавить», «Изменить». Мультикластерность отсюда.
- **Панель разделов**: Главное, Учёт ресурсов, Персонал (поды), Склад (ноды), Покупки (пакеты), Продажи (ингрессы и сервисы), Администрирование.
- **Формы списков**: объекты как документы, пиктограммы «проведён» (Running/Ready, зелёная галочка), «записан, не проведён» (Pending), «помечен на удаление» (красный крестик). Отбор, поиск, «Ещё ▾».
- **Форма объекта**: шапка, табличные части (контейнеры, тома), кнопки «Провести и закрыть», «Записать», «Провести», «Ещё ▾ → Движения документа» — показывает, какие объекты кластера создал этот объект (ownerReferences как проводки Дт/Кт).
- **Отчёты**: оборотно-сальдовая ведомость по ресурсам (счёт 01 — ноды, 10 — тома, 20 — нагрузки), «Расходы по подразделениям» (из КурсыВалют), «Экспресс-проверка ведения учёта» (линтер кластера), «Монитор руководителя».
- **Обработки**: «Закрытие месяца» (мастер из шагов: амортизация — устаревшие API, списание косвенных — сироты, переоценка — rightsizing, финрезультат — отчёт), «Удаление помеченных», «Тестирование и исправление», «Акт сверки».
- **Журнал регистрации** — аудит-лог с фильтрами «Пользователь / Событие / Метаданные / Важность».
- **Окно «Выйдите из базы!»** у всех открытых сессий GUI при обновлении конфигурации.
- **Консоль запросов** — тот же язык запросов, что в CLI.

Техника: Go-бэкенд (прокси к API с правами пользователя, OIDC) + фронтенд на TypeScript/React, вшитый в бинарник. Ставится пакетом `assnetes-gui`.

## 9. Ещё смешное, что стоит сделать

Отобрано из сорока с лишним идей — те, что одновременно смешные и полезные:

1. **HASP-ключ как device plugin.** Расширенный ресурс `оркестратор.бух/hasp`. Под сервера 1С с `hasp` в запросах шедулится только на ноду «с воткнутым ключом» (метка). Без него: «Не обнаружен ключ защиты программы!»
2. **ИТС как подписка кластера.** Secret с датой окончания: без «действующего ИТС» оператор не ставит обновления («Обновления доступны только при действующем договоре ИТС»). На деле это настоящий механизм, который выключает автообновления.
3. **«Честный знак».** Политика допуска образов только с подписью cosign: «Товар не маркирован, оборот запрещён».
4. **Блокировка расчётного счёта.** NetworkPolicy deny-egress на область имён, которая не прошла проверку политик: «Операции по счёту приостановлены решением ФНС».
5. **Кофта на стуле.** Liveness-проба `кофта`: «Сотрудник на месте, ушла в налоговую».
6. **Субконто.** Не больше трёх обязательных меток на объект («мы не банк»): владелец, статья затрат, проект.
7. **Отрицательные остатки.** Флаг кластера «Контроль отрицательных остатков»: выключен — оверкоммит разрешён, а GUI рисует минусовое сальдо красным.
8. **Ввод начальных остатков через 000.** `главбух ввод-остатков` — усыновление существующих объектов в учёт (adoption в kubepkg уже есть).
9. **Красное сторно.** Откат выводится красным с отрицательными числами: «−3 реплики».
10. **Пересчёт итогов** — пересчёт квот и использования, «Тестирование и исправление» с галочками (дефрагментация etcd, проверка ссылочной целостности ownerReferences).
11. **«А сколько надо?»** `главбух сколько-надо` — анекдот про дважды два как команда: подбирает requests по фактическому потреблению (настоящий rightsizing).
12. **Ил-2 Штурмовик** (1С издавала) — `главбух штурмовик`: chaos-тест, который «бомбит» случайные поды не-прод области имён.

## 11. Открытые вопросы — решения за тобой

1. **Бинарники 1С для стенда.** Легальный путь — лицензия для разработчиков с developer.1c.ru. Регистрация привязана к физлицу и телефону. Нужен твой аккаунт, или чей-то из команды: скачать архив платформы для Linux и активировать лицензию. Шаблоны Бухгалтерии/УТ/CRM — есть ли у Ænix доступ к ИТС или к партнёру 1С? Если нет, демо будет на учебных конфигурациях и на нашей демо-конфигурации, а Битрикс — полноценно.
2. **Название и торговые марки.** «1С», «1С:Предприятие» и жёлто-красная гамма — марки фирмы «1С». Публичное «1С:Оркестратор 8» выглядит как продукт 1С. Варианты: оставить как есть с явной пометкой «неофициальная пародия», или пародийно исказить («1Ж:Оркестратор 8», «Ass:Предприятие 8»). Рекомендую второе для названия и логотипа, а «1С» оставить в описаниях: «ставит 1С:Бухгалтерию».
3. **Где публиковать.** Отдельная организация, как tatar-ncf (например `assnetes`), или `tym83/assnetes`.
4. **Имя CLI.** Предлагаю `главбух` (с латинским синонимом `glavbuh`).
